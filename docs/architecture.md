# WatchTogether — архитектура сервиса совместного просмотра

Дата: 2026-11-22 · Статус: базовый проект (v0.1)

## 1. Продуктовая рамка

Приложение для совместного просмотра фильмов и сериалов компанией:

- запуск у одного участника («хост») в локальной сети — остальные подключаются по списку устройств LAN или через туннель (Hamachi / Radmin / ZeroTier / Tailscale — для приложения это просто ещё один IP);
- собственный плеер с управлением «как на YouTube» (горячие клавиши: `Space`/`K`, `J`/`L`, `←`/`→`, `↑`/`↓`, `M`, `F`, `0–9`);
- синхронизация: пауза/продолжение/перемотка рассылаются всем; **любой** участник может поставить на паузу (демократичный режим), при желании — режим «только хост»;
- громкость — строго индивидуальная у каждого клиента (никогда не синхронизируется);
- комнаты и сессии хранятся персистентно — через месяц можно открыть комнату и продолжить с той же позиции;
- источники контента: плагинная система провайдеров (YouTube, LostFilm-зеркала, пользовательские сайты);
- fallback для контента с подпиской/гео-ограничением: хост ретранслирует видео+аудио участникам (WebRTC, этап 2).

## 2. Выбор стека (обоснование)

| Слой | Решение | Почему |
|---|---|---|
| Клиент (UI) | **React + TypeScript + Vite + Tailwind + shadcn/ui** | Быстрый современный UI, единая кодовая база для браузера и десктопа |
| Десктоп-обёртка / установщик | **Electron + electron-builder** (этап 3; альтернатива — Tauri) | Нужен NSIS-установщик для Windows, автозапуск локального сервера, tray-иконка. Electron проще для связки «сервер + клиент в одном процессе»; Tauri легче, но требует Rust-инструментария |
| Локальный сервер | **Node.js + Fastify + Socket.IO** | WebSocket-синхронизация в реальном времени; Socket.IO даёт reconnect, комнаты, ack из коробки |
| Хранилище | **SQLite (better-sqlite3)** | Файл-БД без отдельного сервиса: комнаты, участники, позиции просмотра, провайдеры — всё переживает перезапуск |
| Потоковая ретрансляция (этап 2) | **WebRTC (P2P, хост → зрители)** | Низкая задержка, не грузит сервер; signalling через тот же Socket.IO |
| Добыча ссылок YouTube | **yt-dlp** (внешний бинарь, опционально) | Поиск `ytsearch:` и прямые ссылки на поток; без него — встраивание через IFrame API |
| Парсинг сайтов | **cheerio** + конфиг селекторов провайдера | Зеркала LostFilm меняются → домен и селекторы вынесены в редактируемый конфиг |

Почему не «чистый Electron»: клиент должен открываться и в браузере у друзей (по LAN-ссылке ставить Electron никто не будет). Поэтому сервер **раздаёт собранный фронтенд** как статику — друзья просто открывают `http://<ip-хоста>:<порт>`.

```

│     ├─ discovery.ts    # UDP-broadcast: автообнаружение серверов в LAN
│     └─ providers/      # youtube.ts, lostfilm.ts, custom.ts (плагины поиска)

```

## 4. Модель данных (SQLite)

```sql
rooms(id TEXT PK, name TEXT, password_hash TEXT NULL, control_mode TEXT,      -- 'all' | 'host'
      current_video_json TEXT NULL, position_sec REAL, state TEXT,           -- 'playing'|'paused'
      updated_at INTEGER, created_at INTEGER);
members(room_id TEXT, client_id TEXT, nickname TEXT, last_seen INTEGER,
        PRIMARY KEY(room_id, client_id));
providers(id TEXT PK, type TEXT, name TEXT, config_json TEXT, enabled INTEGER); -- зеркала, селекторы
```

Позиция просмотра пишется в БД при каждом событии синхронизации и периодическим heartbeat → «продолжить через месяц» работает из коробки.

## 5. Протокол синхронизации (Socket.IO)

События (комната = Socket.IO room):

| Событие | Направление | Payload | Семантика |
|---|---|---|---|
| `room:join` | c→s | `{roomId, clientId, nickname}` | вход, в ответ — полный снапшот состояния |
| `sync:state` | s→c | `{video, positionSec, state, serverTime, actorNickname}` | авторитетное состояние (шлётся при любом изменении и при входе) |
| `sync:play` / `sync:pause` | c→s→всем | `{positionSec}` | любой участник (или только хост в режиме 'host') |
| `sync:seek` | c→s→всем | `{positionSec}` | перемотка |
| `sync:setVideo` | c→s→всем | `{video}` | смена источника (url, тип, провайдер) |
| `sync:heartbeat` | c→s | `{positionSec, state}` | каждые 5 с от «ведущих» клиентов — уточнение дрейфа и запись в БД |
| `room:presence` | s→c | `{members:[…]}` | кто онлайн |

Коррекция дрейфа: клиент при воспроизведении сверяет `localTime` с `positionSec + (now − serverTime)`; расхождение > 1.5 с → плавный seek. **Громкость и mute — только локальные**, в протокол не входят.

## 6. Провайдеры контента (плагинная модель)

```ts
interface Provider {
  id: string;                       // 'youtube' | 'lostfilm' | custom id
  search(query: string): Promise<SearchResult[]>;
  resolveWatchUrl(result: SearchResult): Promise<WatchSource>; // прямая ссылка или embed
}
```

- **YouTube**: поиск через `yt-dlp "ytsearch10:…" --dump-json` (если бинарь найден) → воспроизведение через YouTube IFrame Player API с кастомным оверлеем (горячие клавиши наши).
- **LostFilm**: в БД хранится список **зеркал** (доменов). Сервер опрашивает их по очереди до первого отвечающего, парсит выдачу cheerio по селекторам из конфига провайдера. Зеркала редактируются из UI (настройки → источники) — «конкретный ресурс» не зашит в код.
- **Пользовательские источники**: провайдер типа `custom` = JSON-конфиг `{searchUrlTemplate, itemSelector, titleSelector, linkSelector}` — пользователь добавляет свой сайт без пересборки.

⚠️ Юридическая заметка: просмотр подпискного контента (Кинопоиск и т.п.) возможен только при наличии доступа у участника; иначе — ретрансляция с хоста (этап 2), что само по себе может нарушать условия сервисов. Оставляем за пользователем.

## 7. Сетевые сценарии

1. **LAN**: сервер слушает `0.0.0.0:9345`. Модуль discovery шлёт UDP-broadcast `WATCHTOGETHER_DISCOVER` на порт 9346 и отвечает на чужие — клиент показывает «доступные устройства в сети» списком.
2. **Туннель (Hamachi/Radmin/ZeroTier)**: прозрачно — участники вводят IP хоста из туннельной сети, discovery там обычно не работает, поэтому есть ручное подключение по адресу.
3. **Нет доступа к источнику у участника** (этап 2): хост захватывает вкладку/окно плеера (`getDisplayMedia` в Electron — без диалога, через `desktopCapturer`) и отдаёт WebRTC-поток; зритель смотрит «экран хоста», управление всё равно синхронное.

## 8. Дорожная карта

- **v0.1 (этот каркас)**: сервер + комнаты + SQLite-персистентность + синхронизация play/pause/seek + кастомный плеер с горячими клавишами + индивидуальная громкость + LAN-discovery + ручное подключение по IP + заглушка поиска провайдеров.
- **v0.2 (сделано)**: чат комнаты (real-time + история 50 сообщений в БД), пароли комнат при создании и входе (ошибки NEED_PASSWORD/WRONG_PASSWORD), поиск LostFilm по зеркалам (селекторы в конфиге провайдера, правятся из UI), список серий сериала со всех сезонов (обход `/series/<slug>/season_N/` с ретраями), попытка извлечь прямой поток серии (best-effort; плеер LostFilm обфусцирован — при неудаче клиент получает ссылку на страницу серии).
- **v0.2.1 (сделано)**: провайдер LordSerial (зеркала семейства lordserials на DLE: POST-поиск `do=search`, серии из `#soons-tv-ajax` на странице сериала, поток — best-effort из iframe-плеера с подстановкой season/episode). Миграция конфигов провайдеров: сидинг больше не пропускает существующие БД — недостающие провайдеры добавляются, устаревшие селекторы обновляются по `configVersion` с сохранением зеркал пользователя. Версия приложения вынесена в `server/src/version.ts`.
- **v0.3 (сделано)**: Electron-обёртка (сервер поднимается внутри приложения, БД в userData), NSIS-установщик через electron-builder (`npm run dist` → `release/`).
- **v0.2.2 (сделано)**: авторизация на провайдерах. У провайдеров появились `loginPath` и `cookies` в конфиге (миграция: LostFilm → configVersion 3, LordSerial → 2). В Electron — встроенное окно входа (partition `persist:wt-auth`, preload-мост `window.wtDesktop.openAuth/clearAuth`): после закрытия окна куки фильтруются по доменам зеркал провайдера и уходят на сервер (`POST /api/providers/:id/cookies`), серия повторяется автоматически. Куки подставляются во все fetch провайдеров (поиск, серии, поток). Через `GET /api/providers` куки не отдаются — только флаг `hasCookies` (защита от угона сессии в LAN); PUT провайдера без поля cookies сохраняет старые. В браузере — fallback: внешняя вкладка + ручной повтор серии.
- **v0.2.3 (сделано)**: перехват потока и HLS/DASH-плеер. В Electron — скрытое окно (та же persist-сессия, `wt:sniff-stream`): страница сериала → клик по серии в `.episodes-item` → перехват медиа-запросов плеера через `webRequest` (m3u8/mpd/mp4, приоритет HLS). Медиа-прокси `GET /api/proxy/stream`: m3u8 переписывается (сегменты, варианты, URI-ключи — всё через прокси), Range пробрасывается, Referer подставляется, приватные адреса запрещены (SSRF). Плеер: hls.js для m3u8, dash.js для mpd. Клиент при неудаче статического извлечения автоматически запускает перехват; HLS/mp4 играют через прокси, DASH — напрямую с CDN.
- **v0.3.0 (сделано)**: Rutube + очередь + история. Провайдер Rutube: поиск (`/api/search/video/`), поток ролика (`/api/play/options/<id>/` → m3u8-балансер, играет через медиа-прокси с Referer rutube.ru), «серии сезона» — эвристика по шаблону названия «<база> N сезон M серия» (сериалы на Rutube — отдельные ролики канала, API сезонов у таких видео нет). В комнате хранится стабильная ссылка на ролик (kind `rutube`), поток резолвится клиентом при каждом включении (подписанные m3u8 протухают). Очередь (таблица `queue`, события `queue:add/remove/clear`, рассылка `room:queue`): по окончании видео (`video:ended`, с защитой от дублей 15 с) сервер атомарно снимает первый элемент и ставит его с автостартом. История (таблица `history`, upsert по (room,url)): пишется при setVideo/pause/ended, хранит позицию и флаг «досмотрено».
- **v0.3.1 (сделано)**: рабочее пространство комнаты перестроено (плеер во всю ширину, вкладки «Поиск/Серии/Очередь/История» под ним, чат справа на всю высоту, участники компактной строкой). «Серии сезона» Rutube покрывают и следующий сезон: эпизоды несут `season`, «+ все после текущей» сравнивает пару (сезон, серия) — очередь не упирается в конец сезона.
- **v0.4 (план)**: WebRTC-ретрансляция с хоста, автозапуск при старте Windows, tray-иконка, субтитры, мобильный UI.

## 9. Решения-ограничения первого среза

- Видео по прямой ссылке (mp4/webm/m3u8 нативно) и YouTube-embed — сразу; торренты/магнет — не в v0.1.
- Пароли комнат: соль+хеш в БД, проверка на входе (сделано в v0.2).
- Без учётных записей: участник = `clientId` (localStorage) + ник.
