# WatchTogether

Сервис совместного просмотра фильмов и сериалов компанией — в локальной сети или через туннель (Hamachi / ZeroTier / Radmin). Свой плеер с горячими клавишами как на YouTube, синхронная пауза/перемотка для всех, индивидуальная громкость, комнаты и позиции просмотра хранятся в SQLite (можно продолжить через месяц).

Архитектура и дорожная карта: [docs/architecture.md](docs/architecture.md).

## Запуск

```bash
# 1. Собрать клиент (один раз или после изменений в app/)
npm run build

# 2. Запустить сервер — он же раздаёт клиент
npm start
```

Сервер слушает порт **9345** на всех интерфейсах:

- вы: `http://localhost:9345`
- друзья в LAN или туннеле: `http://<ваш-IP>:9345` (адрес выводится в консоль при старте)

### Режим разработки (два терминала)

```bash
npm run dev:server   # API + WebSocket на :9345
npm run dev:app      # Vite на :3000 с прокси на сервер
```

### Проверка синхронизации без браузера

```bash
npm run build && npm start          # в одном терминале
WT_ROOM=<id-комнаты> npm run smoke  # в другом (запускать из каталога app/ не нужно)
```

## Десктопное приложение и установщик (v0.3)

```bash
# Разработка: собранные клиент и сервер, окно Electron
npm run build
npm --prefix desktop run start

# Установщик Windows (NSIS) → release/
npm run dist
```

Приложение поднимает встроенный сервер и открывает окно с клиентом. Данные (комнаты, позиции) в установленной версии лежат в `%APPDATA%/watchtogether-desktop/watchtogether.db` и переживают обновления.

## Выпуск обновления

Установленные приложения обновляются из **GitHub Releases** (не из ветки): при запуске и раз в 4 часа проверяют новый релиз, скачивают его в фоне (только изменившиеся части), показывают на главной «Обновить и перезапустить» — и по нажатию ставят обновление **тихо**, без окон установщика, после чего приложение запускается само. Без нажатия обновление не устанавливается.

Каждая версия — это новая сборка установщика; её делает GitHub Actions (`.github/workflows/release.yml`), собирать exe у себя не нужно:

```bash
# 1. Изменения уже слиты в main (git checkout main && git pull)
# 2. Поднять версию во всех местах сразу (desktop, server, шапка приложения)
npm run set-version -- 0.9.3
git commit -am "v0.9.3"
git tag v0.9.3
git push && git push origin v0.9.3
```

Через ~10–15 минут релиз `v0.9.3` появится на GitHub, и устройства увидят обновление. Сборка откажется публиковать, если тег не на `main` или версия в файлах не совпадает с тегом. Ход сборки — вкладка **Actions** репозитория.

Ручной вариант (без Actions): `npm run dist` с переменной `GH_TOKEN` (токен с правом `repo`) собирает и сразу публикует релиз; без `GH_TOKEN` — только собирает в `release/`.

## Что уже работает (v0.1–v0.2)

- Создание комнат, вход по ссылке, присутствие участников (кто онлайн), пароль комнаты (опционально).
- Синхронизация play / pause / seek: управлять может каждый (или только хост — выбирается при создании комнаты). Пауза ставится автоматически и при окончании видео.
- Чат комнаты: real-time по WebSocket, история последних 50 сообщений хранится в БД.
- Громкость и mute — только локальные, у каждого свои.
- Плеер: прямые ссылки (mp4/webm), HLS-потоки (m3u8 через hls.js) и DASH (mpd через dash.js), YouTube (IFrame API со своими контролами).
- Горячие клавиши: `Space`/`K` — пауза, `←`/`→` — ±5 с, `J`/`L` — ±10 с, `↑`/`↓` — громкость, `M` — звук, `F` — весь экран, `0–9` — прыжок на % видео (работают и в русской раскладке).
- Хранение: комнаты, участники, позиция просмотра, сообщения чата — SQLite (`server/watchtogether.db`).
- Источники: YouTube (поиск через yt-dlp, если установлен; иначе — ссылка на выдачу), Rutube, LostFilm и LordSerial (списки зеркал редактируются в UI: «Источники контента»), свои сайты через CSS-селекторы.
- Rutube (v0.3.0): поиск по каталогу, ролики играют в нашем плеере (поток m3u8 из публичного API через медиа-прокси, полная синхронизация). Кнопка «Серии сезона» собирает текущий и следующий сезон поиском по шаблону названия (v0.3.1) — «+ все после текущей» ставит в очередь весь остаток сериала, включая следующий сезон.
- Очередь просмотра (v0.3.0): общая для комнаты, синхронизируется. Ссылки из поиска (кнопка «+») или полем под плеером; клик по элементу — включить сейчас. Когда видео заканчивается — следующее из очереди стартует автоматически.
- История просмотра (v0.3.0): комната помнит, что смотрели, где остановились и что досмотрено (✓). Хранится в SQLite — можно вернуться через месяц и продолжить.
- Раскладка комнаты (v0.3.1): плеер во всю ширину, под ним вкладки «Поиск / Серии / Очередь / История», справа — участники и чат на всю высоту окна.
- Совместимость с LAN (v0.3.2): клиент у участников, открывших комнату по `http://<ip>:9345`, больше не падает — `crypto.randomUUID` заменён собственным генератором UUID v4 (этот API браузер даёт только на localhost/HTTPS), а копирование ссылки-приглашения получило запасной вариант без clipboard API.
- Точность синхронизации (v0.3.3): сервер считает позицию играющего видео от момента последней записи (раньше снапшот устаревал на срок до интервала heartbeat — до 5 с отставания); heartbeat отставшего клиента больше не тянет общую позицию назад; каждый клиент раз в 2 с сверяет свою позицию с авторитетной и догоняет плавным изменением скорости (0.9–1.2×), жёсткий seek — только при расхождении больше 6 с.
- Независимость от системных часов (v0.3.4): сервер отдаёт позицию + её «возраст» в миллисекундах, клиент досчитывает позицию по своим часам с момента получения. Раньше формула полагалась на `(часы клиента − часы сервера)`, и расхождение системных часов устройств (обычное дело без NTP) при старте перематывало клиента в неверную точку и держало постоянное смещение — слышимое эхо при включённом звуке на двух устройствах.
- Голосовая комната (v0.4.0): панель под чатом — «Подключиться к голосу», мьют микрофона, «не слышать никого» (деафен, как в Discord). Медиа идёт P2P между устройствами (WebRTC-меш, echo cancellation/noise suppression), сервер видит только список участников и ретранслирует SDP/ICE. В браузере микрофон по `http://<ip>` заблокирован (secure context) — голос работает в десктопном приложении WatchTogether.
- Ссылка-приглашение (v0.4.0): у хоста больше не копируется бесполезный localhost — подставляются LAN-адреса сервера; если сетевых адаптеров несколько (LAN, туннели, виртуальные), показываются все варианты ссылок с копированием по клику.
- LAN-discovery (v0.4.0): устройства в списке показывают имя компьютера, а не только IP.
- Трансляция сайта (v0.5.0): вкладка «Трансляция» в комнате. Ведущий (только десктоп-приложение) указывает страницу — она открывается в скрытом заэкранном окне, захватывается со звуком и раздаётся участникам WebRTC-потоком прямо в область плеера (смотреть можно и из браузера). Кнопка «Разрешить управление мышью» пускает клики и прокрутку зрителей в страницу ведущего. Режим «только плеер» (для LostFilm/LordSerial) блокирует навигацию и всплывающие окна на транслируемой странице. Если ведущий отключился — трансляция завершается для всех.
- Главный экран (v0.6.0): компактная раскладка без пустот — ник переехал в шапку, в подзаголовке видны имя устройства и его адрес в сети (что диктовать друзьям), создание комнаты — одна строка + режим/пароль второй, комнаты — плотная сетка в две колонки с относительным временем («сегодня 18:42», «вчера») и статус-точкой, подключение к другому устройству — одной строкой с поиском в сети.
- Туннель в интернет (v0.7.0): кнопка «Открыть доступ» на главной (только десктоп) поднимает бесплатный Cloudflare Quick Tunnel — без аккаунта, своего сервера и статического IP. Публичная https-ссылка работает с телефона на мобильной сети; заодно по HTTPS браузеры разрешают микрофон — голос доступен и без установки приложения. Бинарник cloudflared скачивается при первом запуске в userData. Ссылка открывает полный доступ к серверу — комнаты лучше защищать паролем.
- Исправление установщика (v0.7.1): в сборку не попадал `preload.cjs` — desktop-функции (трансляция сайта, туннель, встроенная авторизация) молча отключались, и приложение вело себя как браузерная версия.
- Улучшения трансляции сайта (v0.7.2): окно трансляции маскируется под обычный Chrome (User-Agent) — сайты вроде LordSerial перестают капризничать; спиннер «Загружаем страницу…» вместо белого экрана у ведущего и зрителей (состояние ретранслируется по комнате); ошибка загрузки страницы видна во вкладке «Трансляция»; ведущий управляет страницей прямо из своего превью (клики и колесо — без включения общего доступа для зрителей), так что авторизоваться на сайте можно внутри самой трансляции.
- Стабильность туннеля (v0.7.3): cloudflared переведён на протокол HTTP/2 (TCP 443) вместо QUIC (UDP 7844, режется провайдерами в РФ — из-за этого гости видели Cloudflare Error 1033); обрыв туннеля теперь виден на главной с подсказкой перезапустить (ссылка будет новой); статус опрашивается каждые 5 с.
- Два провайдера туннеля (v0.7.4): если Cloudflare заблокирован DPI провайдера (диагностировано: SRV-записи argotunnel.com не резолвятся, TLS к edge обрывается), автоматически поднимается Pinggy — SSH-проброс на чистом Node (пакет ssh2, внешний ssh.exe не нужен, он может отсутствовать или ломаться). Обрыв любого провайдера → автоперезапуск с новой ссылкой, которая сама обновляется на главной (у Pinggy бесплатная сессия живёт ~60 минут). Если оба провайдера недоступны — 3 фоновых повтора, затем явная ошибка на главной.
- Полировка туннеля (v0.7.5): страница-сплэш «Загрузка WatchTogether…» вместо белого экрана, пока бандл едет по туннелю; подсказка на главной, что у гостей Pinggy один раз покажет предупреждение с кнопкой «Enter site».
- Проверка туннеля (v0.7.6): cloudflared печатает ссылку сразу, даже когда DPI уже режет туннель — поэтому перед показом ссылки приложение само открывает через неё свой /api/server-info. Не ответил за 25 с — провайдер помечается мёртвым и поднимается следующий. Ссылка в UI теперь всегда проверенная.
- Возврат и восстановление (v0.7.7): подключившись к чужому серверу (по IP или туннелю), десктоп-приложение показывает баннер с кнопкой «Вернуться к моему серверу» — перезапуск больше не нужен; у гостя скрыт блок «Открыть доступ» (он видел чужие комнаты). Потеря связи с сервером (хост закрыл доступ) → оверлей «Соединение потеряно» с переподключением и выходом на главную. Поиск устройств в LAN: каждый сервер знает свой instance-id и не показывает сам себя; broadcast шлётся ещё и directed-пакетами по каждому интерфейсу (VPN-адаптеры перехватывали 255.255.255.255, и ПК не видели друг друга); в списке показывается адрес устройства в вашей подсети, а не виртуальный (WSL/Hyper-V 172.x). Трансляция YouTube: «только плеер» больше не ломает согласительные редиректы (consent.youtube.com → белый экран) — навигация внутри того же сайта разрешена; при вставке ссылки YouTube/Rutube режим «только плеер» снимается автоматически.
- Виртуальная сеть ZeroTier (v0.8.0): Cloudflare Quick Tunnel удалён полностью (trycloudflare.com нежизнеспособен в РФ — блокируется с обеих сторон), встроенным туннелем остаётся проверенный Pinggy. Новый блок «Виртуальная сеть ZeroTier» на главной: детект установленного ZeroTier One и его службы, подключение к сети по ID одной кнопкой (разовый UAC для zerotier-cli), ссылка на скачивание. ZeroTier — работающий в РФ аналог Hamachi с клиентами под Android/iOS: хост создаёт сеть на my.zerotier.com, гости вводят 16-символьный ID, и устройства сами находят друг друга в «Устройствах в сети» (LAN-поиск работает через виртуальный интерфейс) — без ссылок, туннелей и почасовых ротаций.
- Живость трансляции и полный экран (v0.9.0): окно трансляции за экраном Chromium считал «перекрытым» и останавливал отрисовку + душил таймеры — отсюда вечный белый экран и медленная загрузка страниц; отключены occlusion-детекция Windows и троттлинг фоновых окон, фон окна тёмный вместо белого (нет белых вспышек при переходах), захват явно просит 30 fps. Полноэкранный режим трансляции: кнопка «⛶ Во весь экран» поверх видео, чат становится полупрозрачной панелью справа и сворачивается в кнопку; пока панель свёрнута, на ней счётчик непрочитанных «+N». Голосовая комната: уровень звука каждого потока меряется локально (AnalyserNode, 200 мс) — говорящий подсвечивается изумрудным кольцом и полной непрозрачностью, молчащие приглушены до 50%.
- GitHub и автообновления (v0.9.1): код живёт в репозитории MyLitleProger/WatchTogether, релизы публикуются туда же (electron-builder + GH_TOKEN, релиз сразу публичный). Приложение само проверяет обновления при старте и раз в 4 часа (electron-updater): новая версия качается в фоне, на главной появляется баннер «Обновить и перезапустить». «Подключиться» к чужому серверу теперь с предпроверкой: fetch на /api/server-info с таймаутом 8 с и кнопкой «✕ Отмена» — мёртвый адрес больше не уводит на серый экран без выхода. На сервере включён CORS для API (нужен предпроверке; сервер и так открыт в LAN).
- Прокси для трансляции, версия в шапке (v0.9.2): кнопка «во весь экран» не работала — permission-фильтр Electron отклонял запрос fullscreen (разрешены media/clipboard/fullscreen/pointerLock). YouTube в трансляции показывал «Нет подключения к интернету»: VPN пользователя действует только на браузер, а скрытое окно шло напрямую — во вкладке «Трансляция» появилось поле прокси (socks5://127.0.0.1:10808 и т.п., сохраняется локально), страницы трансляции идут через него, а localhost/LAN в обход прокси — комната не ломается. Версия приложения видна в шапке главной (v0.9.2 рядом с названием), в шапке комнаты и в заголовке окна ОС.
- Безопасность, тихие обновления, релизы через GitHub Actions (v0.9.3): см. раздел «Выпуск обновления».
- Новый главный экран (v0.10): при первом запуске — знакомство («как вас зовут»); сверху два главных действия — «Новая комната» (пароль и режим управления спрятаны в «Пароль и кто управляет») и «Подключиться к другу» (адрес + «Найти в сети»); ниже вкладки «Комнаты» (карточки с замком у комнат с паролем), «Медиатека», «Доступ для друзей» (адреса в домашней сети с копированием, ссылка через интернет, ZeroTier — с понятными пояснениями) и «Источники». Выбранная вкладка запоминается.
- Медиатека (v0.10): видео из папок этого ПК для всех устройств дома и гостей комнаты. Папки добавляет только хост (системный диалог в приложении или путь вручную); сканирование в фоне при запуске и раз в 10 минут (новые загрузки торрент-клиента появляются сами). Файлы отдаются по id, а не по пути — за пределы выбранных папок не выйти; поток с Range (перемотка сразу). Играют MP4/WebM/MKV/MOV (кодеки H.264/VP9 + AAC/Opus); AVI/WMV и т.п. показываются серыми — нужна конвертация. Из интернета (туннель) — только участникам комнаты. «Смотреть» на главной создаёт комнату с этим фильмом; в комнате — вкладка «Медиатека» с кнопкой «+» в очередь.
- RuTracker (v0.10): поиск раздач (нужен вход — кнопка «Войти» в «Источниках» или прямо в результатах поиска открывает окно входа на сайт; куки хранятся зашифрованными). Раздача по клику уходит magnet-ссылкой в торрент-клиент ПК; добавьте его папку загрузок в медиатеку — и скачанный фильм появится там. Сайт блокируется в РФ: серверу нужен системный VPN.
- Прокси для трансляции (v0.10.1): окно трансляции по умолчанию выходит в интернет «как Windows и браузер» — через системный прокси/PAC. Раньше пустое поле прокси означало «напрямую», и трансляция шла мимо прокси, через который работал браузер. Во вкладке «Трансляция» — выбор: как в Windows, напрямую, найденные в системе прокси (локальные порты, отвечающие как SOCKS5 или HTTP-прокси, с именем программы: v2rayN, Clash, Hiddify, GOST, SSH-туннель…) или свой адрес. Каждый вариант сразу проверяется: открывается ли через него YouTube и за сколько мс.
- Голос в локальной сети (v0.10.2): браузеры — и окна Electron — дают микрофон только защищённым страницам (https или localhost), поэтому по `http://192.168…` голос работал лишь на самом компьютере-хосте. Теперь сервер слушает ещё и **HTTPS на порту 9443** с собственным сертификатом «WatchTogether» (создаётся сам и покрывает все адреса ПК). В «Доступ для друзей» — ссылки «с голосовым чатом»; в голосовой панели на http-странице — кнопка «Открыть с голосом (https)» (имя переносится). Браузер один раз предупреждает о сертификате. Приложение WatchTogether при «Подключиться» само идёт на https друга и принимает его сертификат — только для частных адресов (LAN, ZeroTier, Hamachi, Tailscale) и только с именем WatchTogether.
- Настройки комнаты (v0.10.2): у создателя комнаты (и на компьютере-хосте) — кнопка «Настройки»: переименование (участники видят сразу), пароль — задать/сменить/убрать, «Скрыть из списка комнат» (скрытая комната видна только создателю и хосту, остальные входят только по ссылке-приглашению), удаление комнаты. Скрыть можно и сразу при создании.
- Меню профиля (v0.10.2): клик по имени справа вверху — смена имени, версия и «Проверить обновления» со статусом («Установлена последняя версия», «Скачиваем… N%», «Обновить и перезапустить»).
- LostFilm: поиск по зеркалам, список серий сериала (все сезоны, обходом `/series/<slug>/season_N/`), попытка извлечь прямой поток серии.
- LordSerial: поиск по зеркалам (DLE), список серий со всех сезонов со страницы сериала, попытка извлечь поток из iframe-плеера с подстановкой сезона/серии.
- Перехват потока в десктопе (v0.2.3): если статический разбор не нашёл поток, страница сериала открывается в скрытом окне, выбирается нужная серия — и перехватывается реальный сетевой запрос плеера (m3u8/mpd/mp4). Работает с обфусцированными плеерами (cdnvideohub и подобными); окно делит сессию с окном авторизации.
- Медиа-прокси (v0.2.3): `/api/proxy/stream` гонит HLS/mp4 через сервер — переписывает сегменты m3u8, поддерживает Range, подставляет Referer. Участникам в LAN видео доступно, даже если их регион/провайдер ресурс не отдаёт. Локальные адреса проксировать нельзя (защита от SSRF).
- Конфиги провайдеров мигрируют автоматически: при обновлении приложения устаревшие селекторы заменяются актуальными, пользовательские зеркала и куки сохраняются.
- Авторизация на источниках (v0.2.2): если серия требует входа, появляется кнопка «Авторизоваться на сайте». В десктопном приложении открывается встроенное окно входа — после закрытия куки сессии сохраняются в конфиг провайдера на сервере, и серия повторяется автоматически. В браузере открывается внешняя вкладка (куки при этом остаются в браузере, повторите серию вручную). Куки не отдаются участникам через API — только флаг «есть/нет», сброс есть в настройках источника.
- LAN-discovery: UDP-broadcast, кнопка «Найти устройства в сети» на главной.

### Известное ограничение LostFilm и LordSerial

В десктопном приложении поток перехватывается автоматически (v0.2.3), ручной обход почти не нужен. Если и перехват не помог (редкая верстка зеркала, гео-блокировка самого сайта), приложение показывает ссылку на страницу серии: откройте её, скопируйте прямую ссылку на видео (mp4/m3u8) и вставьте в поле «Прямая ссылка». В браузерной версии (без десктопа) перехвата нет — там это основной способ. Плановое решение для участников без доступа к источнику — v0.4: WebRTC-ретрансляция видео/аудио с хоста (частично уже закрыто медиа-прокси: трафик идёт через сервер хоста).
